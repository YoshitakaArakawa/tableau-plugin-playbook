# Tableau ダッシュボードの作成と公開

## 目的

Tableau プラグインのスキルとツールだけでも、ワークブックは公開まで進む。ただし、見た目は Tableau の既定のまま（既定の配色・英語のフィールド名・書式なし）になりやすい。このスキルは、作る順番と見た目のルール、TWB の書き方を補い、人に見せられるダッシュボードに仕上げる。

## 前提

- Tableau プラグイン（tableau）が入っていて、Tableau のコネクタにサインイン済みであること。ツールが見つからなければ、利用者にプラグインの導入とサインインを頼んで止まる
- 目指すのは「人に見せられる、整った Tableau のダッシュボード」
- 公開先のプロジェクトは、利用者が依頼で伝える。伝えられていなければ、公開する前に聞く

## 進め方

ダッシュボードを作る依頼では、次の順に進める。★の後は利用者の返事を待つ。それ以外は止まらずに進める。

1. まず Claude のダッシュボード機能で、分析のダッシュボードを作って見せる。数字は Tableau Cloud のデータソースからライブクエリで取る ★
   - Tableau への公開を頼まれるまでは、ここで止まる。気になる点の修正は、この段階で何度でも受ける
2. Tableau でどんなシートとグラフにするかを決める（tableau-dashboard-advisor）
3. 見た目のルール（下記）をどう当てはめるかを、短く伝える ★
4. ワークブックを作る（tableau-workbook-authoring）。次の参照ファイルを読んでから組む
   - [references/twb-skeleton.md](references/twb-skeleton.md): ファイルの土台と、公開で失敗しやすい点
   - [references/twb-pitfalls-and-formulas.md](references/twb-pitfalls-and-formulas.md): 色・数字の書式・名前の書き方
   - [references/look-and-feel.md](references/look-and-feel.md): 見た目の判断と、整えるためのコツ
5. 公開して、画像で仕上がりを確認する
6. 仕上がりを点検し（tableau-viz-critique）、見た目のルールに合わない点を優先して直す。直して公開し直すのは2回まで
7. 公開した数値が、1 のダッシュボードの数値と合っているか確かめる

利用者が手順の途中から頼んだとき（例: すでにある Claude のダッシュボードを Tableau にしてほしい）は、該当する手順から始める。

## サイトとサーバーの決め方

TWB の接続には、Tableau Cloud のサーバー名（例 `xx-yyyy-a.online.tableau.com`）とサイト名が要る。

1. Tableau のツールで、使うデータソースやコンテンツの URL を確かめ、そこからサーバー名とサイト名を読み取る
2. 読み取れなければ、利用者に「ブラウザで Tableau Cloud を開いたときのアドレス」を貼ってもらう。`https://{サーバー}/#/site/{サイト名}/...` の形から取り出す

## 見た目のルール

- **色**: 基本は灰色、目立たせたいところだけ1色。赤は赤字やマイナスなど「悪い値」にだけ使う
- **数字**: 金額はデータの通貨記号（Sample Superstore なら $）と3桁区切り、割合は「%」で小数1桁
- **名前**: グラフの軸・凡例・タイトルは利用者の言語にする。英語のフィールド名をそのまま出さない
- **主要な数字（KPI）**: 小さな見出しと大きな数字で見せる
- **並べ方**: 項目が枠に収まるようにする。収まらなければ上位だけに絞る

利用者が別の見た目を頼んだときは、利用者の指示を優先する。

## 最後に

公開したダッシュボードの名前とリンク、仕上がりの画像、直しきれなかった点を短く伝える。
